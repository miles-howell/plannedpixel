Payment Posting Rewrite

Replacing a 15-year-old WinForms tool that batch-posts member payments into a health-plan admin system, with every SQL statement ported 1:1.

access:
private · work
year:
2026
built with:
C#, .NET, Django, SQL Server

For about fifteen years, finance staff have used the same Windows Forms desktop app to batch-load member payments (ACH, check, cash and credit card) into a third-party health-plan administration system. The vendor has no bulk import that fits how bank and lockbox reports arrive, so this little tool fills the gap.

The rewrite replaces the UI and the plumbing, not the behavior. Every SQL statement is ported verbatim: column order, sentinel dates, empty strings, even the order of ID-sequencer calls. When something has run against production for fifteen years, an odd-looking line is an external contract, not a bug. Anything suspicious gets a QUIRK: comment and a question, never a silent fix.

~ highlights ~

  • Paste rows straight from Excel or a bank report and stage them as a batch
  • Every row is checked against the member’s account before anything is written
  • A batch log for reviewing open and held totals before sending
  • Nothing posts until a person reviews the batch and clicks send

This was a private engagement, so the code isn't public. Ask me about it.
